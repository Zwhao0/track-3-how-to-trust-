# ScopeGuard 项目计划

## 项目说明

ScopeGuard：**Scope-Aware Safety Guardrails for Coding Agents**。本项目面向 NJU Intelligent Software Engineering Track 3「How to Trust」，周期为一周，研究 Coding Agent 在受限任务中的目标选择与副作用控制。

研究问题：

- **RQ1：** Agent 选错目标或产生范围外副作用的频率和类型是什么？
- **RQ2：** 仅使用 Safety Prompt，与使用可执行护栏相比，能否更有效地阻止这些错误？
- **RQ3：** 这些安全处理如何影响正常任务成功率、澄清次数/行为和执行成本？

实验对照设为 Baseline、Prompt、Guard。三组在任务能力、可用工具和预算上保持可比；Prompt 与 Guard 的差异应限于待研究的处理。计划使用 **gpt-6-luna，reasoning medium**，所有组固定相同配置；subagent 不作为实验处理。上述内容是研究设计，不代表已有实验或观测结果。

## 里程碑与验收

下表每一行是独立、可测试、可审查的交付单元。依赖项必须先满足；验收门槛未通过时不得将里程碑标为完成。每项完成证据应保存到仓库或实验记录中，内容只反映实际发生的事实。

| 里程碑 | 交付范围 | 依赖 | 验收门槛 | 回退方案 | 完成证据 |
|---|---|---|---|---|---|
| **M0 文档与 bootstrap** | 研究范围和协作规则；一周计划；Python 3.11+ 项目骨架；uv 与 pytest 开发入口；TaskSpec 初步设计；可离线运行的 mock 入口。 | 无 | 新环境可按文档安装依赖并运行 pytest；mock 入口无网络/API 调用且输出明确；TaskSpec 字段及边界在文档中说明。 | 缩减为文档、最小配置和纯离线 smoke/mock；若依赖安装不可用，记录原因和环境，不引入在线依赖。 | `AGENTS.md`、本计划、依赖/项目配置、mock 使用说明、实际 pytest 与离线运行命令及输出。未执行的命令不记作通过。 |
| **M1 隔离任务运行器** | 读取公开 TaskSpec，在独立工作区运行固定模型或显式 Mock；定义共用函数接口、文件访问边界和预算，保存完整工具轨迹与终止原因。不得给代理任意 shell；Oracle 不进入代理侧。 | M0 | 可复现地启动、超时终止并回收进程；越界访问尝试被边界阻断或显式拒绝；日志记录输入、工具调用和终态；隔离测试覆盖通过。 | 若隔离不可用则停止真实执行；若只缺凭据或模型访问，则可验收离线 Runner，真实函数调用另记未验证。 | 配置与接口说明、隔离测试结果、受控正常/拒绝/超时轨迹，以及真实函数调用验证的通过或未完成状态。 |
| **M2 确定性评测器** | 设计冻结的任务结果判定、范围外副作用检测、错误分类和 Oracle 接口；只有评测器可访问 Oracle。 | M0；M1 的已验收快照与轨迹格式 | 固定输入产生固定评分；正反例和边界例覆盖评分规则；Oracle 不可被任务代理读取；评分版本和测试集有版本标识。 | 如自动判定含糊，则在冻结前缩小任务范围；不可判定的正式结果记为未知并保留。 | 评分规则版本、测试夹具与结果、Oracle 访问边界检查及未知状态记录。 |
| **M3 策略与 staged executor** | 定义范围策略；执行前检查和分阶段执行器；记录允许、拒绝、需澄清及原因；仅在 Guard 实验组启用对应可执行护栏。 | M1、M2 | 策略决策确定且有测试；执行器在提交副作用前检查目标和范围；允许、拒绝及待澄清决策均可审计，拒绝或提交失败无部分变更；共享运行能力不因实验组而变。 | 若策略无法安全表达某类任务，则将该类任务从可执行集合中排除并记录，不降级成未受控执行。 | 策略版本、执行阶段日志、允许/拒绝测试结果和共享能力对照说明。 |
| **M4 澄清流程** | 规定何时向用户澄清、问题格式、等待/超时处理和响应后的恢复；记录澄清行为以回答 RQ3。 | M1、M3 的策略与事件接口 | 模糊目标、缺少必要范围信息和信息充分任务的用例均有预期行为；澄清记录可计数；不确定时不擅自扩大任务范围。 | 无法支持交互时，将澄清事件作为明确终态或使用预先记录的响应；不得假装用户已答复。 | 澄清规则、用例与测试结果、脱敏事件记录及计数定义。 |
| **M5 基准任务与预注册** | 构造并冻结覆盖正常任务、错误目标诱因和范围外副作用风险的任务集；记录分组、运行预算、随机化、指标、排除规则和成本口径。 | M2；M1 的可复现执行接口；M3/M4 的实验处理定义 | 任务、Oracle、指标和排除规则在正式运行前锁定并版本化；三组使用相同任务与预算；试运行与正式数据分开存放。 | 一周周期内无法达到合理覆盖时，缩小任务集并明示外部有效性限制；不以运行后筛选代替预先规则。 | 基准版本、任务与标签清单、预注册/实验配置、预算表和变更日志。 |
| **M6 实验与消融** | 在 Baseline、Prompt、Guard 上执行可复现实验；按计划做消融；统计 RQ1–RQ3 的指标与不确定性；维护失败样本。 | M5 冻结；M1–M4 相应路径通过验收，含 M1 真实调用验证 | 至少保留一个任务在三组的真实运行供回放；固定 gpt-6-luna / reasoning medium 与组间预算；保留所有有效运行、错误和失败；消融一次只改变预先定义因素；复算结果与原始记录一致。 | 若 API/预算/时限阻碍完整实验，报告实际完成的样本和缺口，优先保留平衡的试验切片；无可核验真实结果时本门槛未通过。 | 原始运行记录、模型/成本配置、失败清单、分析脚本与输出、消融配置及复算记录。 |
| **M7 Dashboard、论文与交付** | 展示实验状态和结果的只读 dashboard；撰写研究报告/论文；整理开源许可、源码、数据字典、复现实验步骤、现场演示脚本和限制。 | M6；结果与分析冻结 | 可回放同一任务的 Baseline/Guard 真实轨迹，dashboard 数值可追溯到分析产物；报告回答 RQ1–RQ3 并披露失败、限制和偏差；从干净环境按说明复现离线部分。 | 时间不足时交付静态结果页/图表和完整文字报告；不能复现的部分明确标记，不宣称已复现。 | dashboard 截图或构建产物、报告、复现说明、交付清单及最终状态记录。 |

## 一周排期（目标）

- 第 1 天：M0；验收并获批后开始 M1。
- 第 2 天：M1 验收、M2。第 3 天：M3。第 4 天：M4、M5。
- 第 5–6 天：M6。第 7 天：M7 与演示排练。

每天的安排仅用于估算工作量。每次只实施一个获批里程碑，依赖或验收不满足时采用上表的降级方案并记录缺口。M6 不得用正式结果反向改评分标准。
